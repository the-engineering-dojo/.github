# 🤝 Contributing to The Engineering Dojo

Thanks for being curious! This is a learning space, not a sprint to ship the most features.

## 🚪 Pick a way in

1. **📚 Learn:** read a short note in [Engineering Handbook](https://github.com/the-engineering-dojo/engineering-handbook).
2. **💬 Discuss:** ask a focused question or propose a challenge in the appropriate repository's Issues.
3. **🧪 Practice:** reproduce a problem, document assumptions and compare alternative approaches.
4. **👥 Review:** help someone else by asking clarifying questions and pointing to evidence.
5. **📝 Share:** write what surprised you, what failed, and what you would change.

## ✅ A good contribution

- Starts with a clear question: **What problem are we trying to understand?**
- States assumptions and non-goals before choosing a pattern.
- Uses a small reproducible example or a diagram whenever useful.
- Explains how the result was checked, including any uncertainty.
- Links to official docs or a credible source when making nontrivial technical claims.
- Avoids unnecessary dependencies, filler text, and decorative complexity.

## 🤖 AI-assisted work

AI is allowed for tutoring, feedback, research, drafting, and implementation **when implementation is authorized**. Contributors remain responsible for checking factual claims, testing code, and explaining trade-offs. Avoid submitting large AI-generated blobs that no one understands. In PRs, briefly note material AI assistance when relevant.

## 🧭 Pull requests

- Open a focused PR rather than bundling unrelated ideas.
- Describe **why**, **what changed**, **how you verified it**, and **what remains uncertain**.
- Request at least one peer review for substantial changes.
- Discuss the reasoning, not the author's skill level.
- Draft PRs are welcome, especially for work-in-progress explanations.

## 🧠 Learning notes

Prefer this structure: **Question → Hypothesis → Experiment → Evidence → Trade-offs → Takeaway**.

## 🚫 Scope for now

We are in **planning/documentation mode**: do not add application code or infrastructure implementations without a separately agreed challenge and review scope.

## 💬 Respectful collaboration

Be welcoming, patient, and specific. Disagreement is healthy; personal attacks and harassment are not. See [Code of Conduct](CODE_OF_CONDUCT.md).
